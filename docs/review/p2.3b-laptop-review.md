## Findings, by severity

### B1. Medium: on a special day, while hours are not set, the front page says "Closed this week."
- **Where:** `src/lib/store-hours.js:36-39`. `openStatus()` looks 8 days ahead for the next opening. A day with no
  override and `hours: null` gives `span() = null`, so the loop finds nothing and returns `{ known: true, open: false,
  next: null }`. Then `render.js:186` (`headline`) gives `'Closed this week.'` and `render.js:173` (`openText`) gives
  a bare **Closed**.
- **What breaks:** today's real state is hours not set (Q2). The owners add Thursday 2026-11-26 "Closed for
  Thanksgiving". On Nov 26 the hero h1 reads **"Closed this week."** and the strip on every page reads **Closed**,
  although the shop opens as normal on Friday. A special-hours day (for example a release day, noon to 4 PM) does the
  same from 4 PM on. Players who check the site decide the shop is shut for the week.
- **Fix:** in `openStatus`, stop looking ahead at the first day whose hours are unknown, and return a value that says
  so (for example `next: undefined, later: 'unknown'`). Have `headline` and `openText` then say "Closed today." plus
  the override note, and never "this week". Add tests on the real server with `hours: null` and one override: closed
  today gives "Closed today." and never "this week"; special hours after closing time give the same. Put these next to
  the F4 render test from #11.

### B2. Medium: the room photo can't be uploaded from an iPhone or iPad, and the error blames the file
- **Where:** `src/pages/admin.astro:875-878`. `photoPicker` encodes with `canvas.toDataURL('image/webp', 0.82)` and
  refuses anything that doesn't start with `data:image/webp`. `server.js:337` (`DATA_WEBP`) and the upload name regexes
  (`server.js:150`, `:487`) also accept only WebP.
- **What breaks:** Safari's canvas does not encode WebP. It quietly returns PNG, and every iOS browser uses Safari's
  engine. DESIGN 9 builds the admin for a tablet at the counter. An owner on an iPad who picks a normal JPEG from
  Photos gets "That file is not a picture we can use. Please choose a JPEG, PNG or WebP photo." That message
  contradicts itself, and no photo can be added from that device. A second, smaller problem: a busy 1024x768 photo
  can go over the server's 400 KB limit (`takeWebp`). The server's `file_size` error is then shown as "Please choose
  one under 15 MB", although the file was 3 MB. **Check on the owners' iPad before fixing** (I can't run Safari
  here). The picker comes from VFW, so VFW probably has the same gap.
- **Fix:** if the WebP output doesn't start with `data:image/webp`, encode as `image/jpeg` instead. Accept
  `data:image/jpeg` with the same fixed dimensions on the server (read them from the JPEG SOF marker, or let `sharp`
  read them and re-encode to WebP). Widen the two upload-name regexes if a `.jpg` can be stored. Give the server's
  `file_size` its own message: "That photo has too much detail to save. Try another one."

### B3. Low: after an address change, the "New here?" Directions button still goes to the old address
- **Where:** `src/pages/new-here.astro:75`. This `href={maps}` is built at build time from `store.json` and sits
  outside every `<!--mg:*-->` marker. The address above it (`nh-here`) is live; the button is not.
- **What breaks:** if the shop moves, or a typo in the street is fixed in Store info, the New here? page shows the new
  address with a Directions button to the old one, until someone rebuilds. `test/store.test.js` doesn't catch it
  because it serves its own hand-made templates, not the built pages.
- **Fix:** move the `<p class="visit-acts">` inside the `nh-here` marker, or add a marker around it. Add a
  `public.test.js` check on the real build: after a Store info address change, the old street (and `445+York`) appears
  nowhere on `/`, `/new-here/`, `/events/` or an event date page.

### B4. Low: special days never expire, and once there are 60 every Store info save is refused
- **Where:** `src/lib/store.js:53` caps `hourOverrides` at 60 (`MAX_OVERRIDES`), and `clean()` (`:83`) keeps past dates
  forever. Nothing warns about a date in the past.
- **What breaks:** after a few years of holidays and release days, a phone-number change fails with "At most 60
  special days." until someone deletes old rows by hand. The list is sorted oldest first, so stale rows push today's
  rows down. Separately, a mistyped year (2025-12-24 entered in November 2026) saves without a word and does nothing.
- **Fix:** have `clean(b, prev, today)` drop overrides before `today` (the server passes `etDay()`), and have
  `validate` say "That date has passed." for a new past date. Add one test for each.

### B5. Low: `tools/enhance-video.sh` breaks on Windows checkouts, can overwrite its own input, and trusts the clip file
- **CRLF (where: no `.gitattributes`):** with `core.autocrlf=true` (true on this Laptop), `git ls-files --eol` shows
  the script as `i/lf w/crlf`. Git Bash then reads `set -euo pipefail\r` as an invalid option and leaves a trailing
  `\r` on every variable. The script fails on any fresh Windows clone, including the Desktop's next one. Fix: add a
  `.gitattributes` with `*.sh text eol=lf`.
- **Input clobber:** `bash tools/enhance-video.sh media/clip.mp4 clip` writes `tools/../media/clip.mp4` with `-y`
  while ffmpeg is reading `media/clip.mp4`. The two paths are different strings, so ffmpeg's same-file check misses
  them, and the source clip is truncated. `media/` is gitignored, so the clip can't be recovered. Fix: reject the run
  when `realpath "$in"` equals `realpath -m "$out/$name.mp4"`, and check `name` with `[[ $name =~ ^[a-z0-9-]+$ ]]`.
  That also stops `../` writing outside `media/`. Check that `h` and `secs` are whole numbers and `h` is even,
  because libx264 rejects an odd height. Print usage when an argument is missing; with `set -u` the user now gets
  "unbound variable".
- **Untrusted clip:** the clips come from TikTok, Instagram or Facebook through download tools. ffmpeg picks the
  demuxer by content, so a ".mp4" that is really an HLS or concat playlist can pull local files or URLs into the
  frames, and the result is meant for the public site. Fix: put `-protocol_whitelist file -f mov` before `-i` on the
  first command. The later steps read our own MP4.
- Quoting is otherwise correct: every expansion is double-quoted.

### B6. Low: the preview drift test checks class names, not what the card says
- **Where:** `test/store.test.js`, last test. It passes when each class and `data-*` name from `card()` appears
  anywhere in `pvCard`'s source text.
- **What breaks:** the words can drift and the test stays green. One drift exists today: with 1 seat, `render.js`
  says "1 seat left" but `pvCard` (`admin.astro:680`) says "1 seats left". If `render.js` changes "seats left", "Just
  show up. No sign-up needed." or the "Arrive by ... to keep your seat." line, the preview keeps the old words.
- **Fix:** add a list of the card's fixed phrases (taken from `render.js` `actionArea` / `arriveLine` / `tagRow`) and
  assert that each one appears in `pvCard`. Make `pvCard` use the singular for 1 seat.

### B7. Low: the tagline hint promises something the site doesn't do
- **Where:** `src/pages/admin.astro:957`: "Used in the description Google shows."
- **What breaks:** the meta descriptions are fixed per page at build time (`Base.astro:23`). The tagline only feeds the
  HobbyShop JSON-LD `description`, which Google doesn't use as the search snippet. The owners edit the line and
  Google's snippet never changes.
- **Fix:** reword the hint to "Part of the shop details search engines read.", or send the tagline into the front page's
  meta description through the `head` marker.

## Looks good
- **Injection.** `store-render.js` builds only with `h`. The hostile-row test writes past `clean()` straight into the
  DB and checks every page, JSON-LD and the `.ics`. The `<!--mg:visit-->` region contains the old `mg:hours` marker,
  and the lazy marker regex replaces the outer region whole, so nothing is printed twice. Chip colours come from a
  constant map. The icon paths come from the `ICONS` constant only (D25 (6)). The preview is a same-origin frame with
  no `srcdoc` and no `document.write`.
- **Live edits.** Facts are read per request from the kv row and seeded once (a restart doesn't put the file back,
  and that is tested). HTML is `no-cache`. `.ics` LOCATION, HobbyShop JSON-LD, the event date page and every marker
  use `ctx.store`. Opening the preview frame doesn't add page views, because `stats.record` skips the signed-in admin.
- **API.** The API needs a session, checks the origin on writes, rate-limits, caps the body at 32 KB (under the 256 KB
  HTTP cap) and returns per-field errors that map back to the right control. The audit log names the changed fields,
  not the values. The room photo must be one the picker offers (D25 (7)), and the room photo can't be deleted while it
  is in use.
- **Midnight.** "24:00" and "00:00" are treated the same in `store-hours.js`, `fmtTime` ("midnight") and JSON-LD
  (`23:59`). An overnight close is tested on the real server.
