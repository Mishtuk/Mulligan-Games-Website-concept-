## Findings, by severity

### F1. High: "Bring it back" and "Undo" fail for every slot of an "On these dates" series (prereleases)
- **Where:** `src/pages/admin.astro:505` sends `DELETE admin/series/<id>/exceptions/${enc(o.slot)}`. `server.js:451` splits `url.pathname`, which the WHATWG URL parser leaves percent-encoded. `server.js:408` passes that raw segment to `deleteException()`.
- **What breaks:** a slot key like `2026-11-08T15:00` arrives as `2026-11-08T15%3A00`. The `DELETE ... WHERE date = ?` matches nothing, so the API returns 404 and the toast says "Something went wrong". Staff who cancel the 3 PM prerelease slot by mistake can't undo it from the admin, and neither the Undo button nor "Bring it back" works. Plain-date keys (weekly, nth and one-off series) have no `:`, so they work, and that is why `test/public.test.js:105` passes.
- **Fix:** in `seriesApi`, decode the segment with `try { date = decodeURIComponent(date) } catch { return bad('not_found', 404) }`, or decode all segments once in `adminApi`. Add an API test: POST a cancel on `pre` at `2026-11-08T15:00`, DELETE it with the encoded key, and expect 200 with the slot back on. This also closes the open P2.2b D23 box.

### F2. Medium: the public tests are a time bomb and fail from 2026-10-31
- **Where:** `test/public.test.js:92-95` fetches `/events.ics` with no `?now=` and looks for `UID:fnm-20261030@`. `test/public.test.js:101-102` looks for `?date=2026-10-30` in `/sitemap.xml`. `server.js:259` builds the sitemap from `etDay()`, so it ignores `?now=`.
- **What breaks:** once the real date passes Oct 30, the feed (it starts at today) and the sitemap (it lists today onward) both drop that date. The test then fails, CI goes red and nothing in the code changed.
- **Fix:** request `/events.ics?now=${NOW}`. Have `/sitemap.xml` use `publicCtx(url).now.ymd` (the `?now=` clock already works only outside production, per D24 (4)). An alternative is to compute `DATE` as the next Friday after the real today.

### F3. Medium: editing a series silently drops its one-date changes and cancellations
- **Where:** `server.js:390-395` (PUT series) and `src/lib/events.js:70` (the slot key is `date` or `date + 'T' + slot start`).
- **What breaks:** suppose the Nov 8 3 PM prerelease slot is cancelled, and staff later edit the series to move that slot to 3:30. The slot key becomes `2026-11-08T15:30` and the stored cancel (`...T15:00`) matches nothing. The date shows as on again on the card, the date page, the JSON-LD (EventScheduled) and the feed, and the feed UID changes too, so a calendar that subscribed or imported the old entry keeps a stale copy. Changing a weekly series' weekday, or a one-off's date, orphans its exceptions the same way. Nothing tells staff.
- **Fix (pick one):** on PUT, carry over exceptions whose slot changed only in its start time. Or refuse the edit with a field error naming the affected dates ("3 dates have changes or cancellations; bring them back first"). Or at least list orphaned exceptions in the Events view. Add a test for this.

### F4. Medium (latent until P2.3b): one holiday override with unconfirmed hours empties the Events page, and nothing is logged
- **Where:** `src/lib/render.js:398` calls `ctx.store.hours.find(...)` whenever `hoursFor()` returns `known`. `hoursFor()` (`src/lib/store-hours.js:71-72`) returns `known: true` for any override even while `store.hours` is `null`, which is the state today (Q2). `src/lib/store-hours.js:84` also runs `toMin(null)` when an override or weekly row has `open` but no `close`. `src/lib/state.js:37` catches the throw and serves the marker's placeholder with **no log line**.
- **What breaks:** the owners add "Closed Thanksgiving" before they confirm weekly hours. For the week before Thanksgiving, `/events/` returns 200 with "The event list is loading from the server", and nobody sees an error. An override with no `close` does the same to the strip, the hero, This week and the hours table on every page.
- **Fix:** use `Array.isArray(ctx.store.hours) && ...` at line 398. Treat a missing `close` as closed, or validate the overrides when P2.3b makes them editable. Log the marker name and error in `injectMarkers`' catch, keeping the fail-open behaviour. Add a render test with `hours: null` plus one override, and one with hours known (the closed-day branches in `events()` and `week()` are never rendered in tests).

### F5. Low: `.ics` SEQUENCE is not monotonic
- **Where:** `src/lib/ics.js:174`. SEQUENCE is 1 for any change or cancel and 0 otherwise.
- **What breaks:** after "Bring it back" on a cancelled date, the per-date file and the feed go back to SEQUENCE 0. A client that honours SEQUENCE (Outlook importing a per-date file, for example) treats 0 as older than the cancelled copy (1) and keeps the date cancelled. A change followed by a cancel stays at 1 with the same UID, so the client relies only on DTSTAMP.
- **Fix:** derive SEQUENCE from a value that only goes up. For example, store `updated` as a timestamp (or keep a per-exception revision counter), set SEQUENCE to seconds since a fixed epoch, and keep a "brought back" tombstone instead of deleting the row.

### F6. Low: production without `PUBLIC_URL` publishes localhost links
- **Where:** `server.js:34`, and `startupProblem()` in `src/auth.js:141` does not check it.
- **What breaks:** canonical URLs, Event and HobbyShop JSON-LD `url`, `sitemap.xml`, `.ics` URL/Details and the copied post text all point at `http://localhost:8080`. The CSRF allow-list (`origins()`) also includes that value.
- **Fix:** have `startupProblem` refuse to start in production unless `PUBLIC_URL` is an `https:` URL. Add this to the P3.2 deploy check.

### F7. Low: duplicate slots in an "On these dates" series are accepted
- **Where:** `src/lib/events.js:130`.
- **What breaks:** two entries with the same date and start (an easy double-add) give two occurrences with the same slot key. One cancel or change hits both, and the date page has duplicate element ids (`c-`/`t-${key}`), so `aria-labelledby` points at the wrong card.
- **Fix:** reject duplicate `date + start` with "That date and time is already in the list."

### F8. Low: the external headcount is keyed by day, not by slot
- **Where:** `src/lib/seats.js:47` (`externalCount?.[o.date]`) and `validate()` (`isDate(d)` keys only).
- **What breaks:** two external-sign-up slots on one day show the same "N registered", the same D23 problem in a smaller place.
- **Fix:** key by `o.slot` and accept slot keys in `validate()`.

### F9. Low: an event that runs past midnight disappears from "On now" at 00:00
- **Where:** `src/lib/render.js:69` and `:200-201`. `upcoming()` and `hero()` start at `now.ymd`.
- **What breaks:** a 7 PM to 1 AM event drops off the hero's "On now" and This week at midnight, even though `endM()` says it is still running.
- **Fix:** expand from `addDays(now.ymd, -1)` and keep the `endM > now.m` filter.
